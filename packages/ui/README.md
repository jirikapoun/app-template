# @app/ui

The UI layer of the application: the views rendering API responses as HTML pages, and the `App` layout they share. Views are React components, rendered on the server and hydrated in the browser.

## Contents

```
src/
├── App.tsx        layout: the whole document (<html>, <head>, <body>), the PrimeReact provider and style sheet
├── view/          views, one per file (StatusView.tsx, …)
├── style/         stylesheets: main.css, the entry stylesheet with the theme and Tailwind CSS
├── manifest.ts    client manifest, re-exported for the server
└── env.d.ts       ambient declaration of the virtual manifest module
public/            public files (favicon.svg), served at the root URL
tailwind-icons.ts  Tailwind plugin for the icon classes
vite.config.ts     production build
```

## Public interface

| Export | Source (development) | Build (production) |
|---|---|---|
| `@app/ui/view/<View>` | `src/view/<View>.tsx` | `dist/ssr/view/<View>.js` |
| `@app/ui/manifest` | `src/manifest.ts` | `dist/ssr/manifest.js` |
| `@app/ui/package.json` | — | — |

- **Views** are imported by `@app/api`, which assigns them to routes.
- **The manifest** is passed by `@app/api` to the rendering middleware: `rendering({ manifest })`.
- **`package.json`** is exported so that `@app/server` can find the browser bundle (`dist/client`) and copy it.

## Writing views

```tsx
const StatusView = view<typeof statusResponses.getStatus>(({ uptime }) => (
  <App title="Status">
    <div>
      <strong>Uptime:</strong> {uptime} milliseconds
    </div>
  </App>
))

export default StatusView
```

- **One view per file** in `src/view/`, exported as default, as a variable. Files in this directory are what the Vite plugin treats as views.
- **The component is the first argument of `view()`**, typed by the response schema.
- **Views render the whole document** by wrapping their content in `App`, which gets the page title.
- **Views run in the browser too:** import only browser-safe code (type-only imports of schemas are fine), and keep the first render deterministic (no `Date.now()`, `Math.random()` or locale formatting).
- **Effects must survive Fast Refresh:** keep values that should persist in state, as `StatusView` does.
- **Public files** are referenced by their URL (`/favicon.svg`), never imported.
- **PrimeReact components** are imported from their module directory (`import { Inplace } from 'primereact/inplace'`), never from a file in it or from the package root; ESLint reports both and fixes the file imports the editor suggests. Their styles are part of the server-rendered page thanks to a patch of PrimeReact. See [PrimeReact](../../docs/primereact.md).
- **Styles** are Tailwind utilities in the markup; colors that should follow the theme use the theme utilities (`bg-surface-card`, `text-primary`). Icons are classes too: `icon-[prime--refresh]` where PrimeIcons has the icon, `icon-[tabler--…]` otherwise. See [Styling](../../docs/styling.md).

See [Server-side rendering and hydration](../../docs/rendering.md#views) and [Hot reloading](../../docs/hot-reload.md#requirements-for-views) for the reasons behind these rules.

## The manifest

`src/manifest.ts` re-exports the client manifest generated by the `maveric()` Vite plugin (`virtual:maveric/manifest`), typed as `ClientManifest`. During development, the dev server generates it; in the production build, `@app/ui` generates it from its own browser bundle. The explicit type keeps the virtual module out of the package's type declarations.

## Build

`rimraf dist && vite build && tsc -p tsconfig.build.json`:

1. Vite builds the `client` environment: the browser bundle with the runtime, the views, a `vendor` chunk and the stylesheet, in `dist/client`, for the browsers listed in the root `package.json` (see [Styling](../../docs/styling.md#browser-support));
2. Vite builds the `ssr` environment: the server-side modules (views, `App`, the manifest), one file per source module, in `dist/ssr`;
3. `tsc` emits the type declarations into `dist/ssr`.

```
dist/
├── client/    browser bundle (copied into the server's output)
└── ssr/       server-side modules and type declarations
```

The package is built by Vite rather than `tsc` because it produces the browser bundle and generates the manifest from it, and because views importing stylesheets or images need a bundler. See [Vite setup](../../docs/vite.md#appui).
